Machine Learning in ABC Mapper: Random Forest Implementation Report

This report outlines the recent modifications made to the ABC synthesis tool’s mapping phase to integrate an ML-based heuristic (specifically, a small Multi-Class Random Forest classifier) for determining cut survival during technology mapping.

1. What We Did

We extended the traditional ABC map command (technology mapper) to dynamically select which cuts are retained dynamically using Machine Learning instead of using standard static heuristics like absolute dominance or constant cut volume limitations.

To achieve this: - We modified the internal representation of cuts to log various cut topology features (size, max depth, logic level, etc.) and labeled them based on whether they would “survive” under strict algorithmic structural heuristics (dominance and volume). - We generated and captured testing data using varying ABC_CUT_HEURISTIC runs. - We designed a lightweight Python training pipeline exclusively focusing on a Random Forest classifier. - We directly transformed the small trained Random Forest decision trees into inference code (ml_inference.h), so that ABC natively executes ML predictions at C-level without heavy external ML inference dependencies (like TensorFlow or ONNX runtime).

2. Dataset Collection & Heuristics Used

The dataset was gathered by executing ABC across multiple testbench designs (.blif files in blif_files/) by explicitly executing run_experiments.sh.

To gather supervised training labels and feature profiles, we initially leveraged three traditional “score” heuristics: 1. Dominance: Prioritizes preserving cuts if they are not totally dominated structurally by other identical subsets of the logic cone. Handled using logical subset checking. 2. Volume: Handled cuts heavily based on overall logical breadth; specifically simulating survival if the cut has 4 or fewer leaf nodes (nLeaves <= 4). 3. Random: An arbitrary parity-based heuristic to keep ~50% random cuts and trivially simple 1-leaf cuts. Used purely as a comparative baseline.

For each mapping node, cuts_all_features.csv dumped extracted model features, and cuts_survivors.csv boolean outcomes based on the heuristics above. We combined the survivability values to construct labels reflecting the relative “quality” of a cut.

3. Features Extracted (X)

We generated the header logic by extracting specific mathematical and topological features per cut. The feature vector array (float features[9]) includes: - nLeaves: Total number of leaf variables. - nVolume: An approximate measurement of the internal mapping subset logic volume. - max_level: Maximum circuit propagation depth. - avg_level: Aggregated average depth across all leaf inputs. - random_val: Baseline uniform distribution values appended for normalization/validation parity checks. - uTruth: The raw truth table signature (integer). - uTruth_popcount: Structural bit-count complexity of the boolean truth expression. - max_leaf_refs: Total external graph references per leaf variable. - max_arrival: The locally estimated worst-latency signal arrival times.

4. Modeling Strategy and Training

We opted explicitly for a Multi-Class Random Forest Classifier implemented via Python’s scikit-learn taking into account the balance between rapid inference cycle execution in C natively vs model complexity.

Model Particulars: - Estimators (n_estimators): 15 decision trees. - Depth (max_depth): Strict ceiling of 8 steps to enforce quick bounded runtime. - Classes: 3 output classes (0=Poor, 1=Average, 2=Good), synthesized respectively by blending dominance logic and maximum volume sizes (score = s_dom + s_vol). Training leveraged class_weight='balanced'.

During execution, train_model.py reads the feature dataset, trains RandomForestClassifier, measures classification accuracy against the targets, and recursively translates each estimator tree structure directly through an abstract syntax translator block into inline if/else boundaries encapsulated in standard C functions.

5. Main Extracted Base Modifications

Deep structural interventions were introduced inside src/map/mapper/:

  • mapperCut.c: We inserted a feature extraction and dataset logging routine, Map_CutMLDump, which computes max levels, total arrivals, logic signatures, etc., right before standard native dominance filtering (Map_CutFilter). We modified Map_CutFilter’s main routine to allow ABC_CUT_HEURISTIC overrides (e.g. bypassing filtering constraints and strictly allowing Volume or Random filtering based on runtime arguments).
  • mapperCore.c: Captured exact end-stage metrics upon mapping termination by storing final area (AreaFinal), delay (fRequiredGlo), and tracking exactly how many total mapping permutations naturally survived filtering logic into cuts_qor.csv.
  • mapperInt.h: Modified Map_CutStruct_t_ internal framework to contain an intrinsic mapping string integer cut_id per cut structure layout to natively cross-reference data across our multi-pass data collection loops reliably.
  • mapperCutUtils.c: Dynamically allocated sequential unique cut_id properties inside memory pool management via Map_CutAlloc.

Summary: We substituted hardcoded technology map pruning paths with a robust, data-conscious mechanism mapping feature relationships. By employing small-scale, balanced Random Forest logic integrated at the ground-level core logic (via C-header injection strategy), ABC accurately balances complex graph traversal while keeping mapping compute operations constrained.
